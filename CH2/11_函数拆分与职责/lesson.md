# 第 11 课：函数拆分与职责划分

## 本课目标

完成本课后，你应该能够：

- 根据输入、处理和输出拆分函数；
- 为函数设计清晰的职责和命名；
- 区分计算函数和 I/O 函数；
- 识别过大函数、重复逻辑和隐藏副作用。

## 1. 为什么要拆函数

把所有代码都写在 `main` 中，短程序还能阅读；需求增长后，定位问题和复用逻辑会越来越困难。拆函数不是为了让文件看起来更长，而是为了让每个函数承担一个容易说明、容易测试的职责。

一个好的函数通常能用一句话描述，例如“计算三个成绩的总分”“根据总分计算平均分”“打印成绩报告”。

## 2. 接口先于实现

设计函数时先确定：

- 函数名表达什么动作或结果；
- 参数分别代表什么；
- 返回值是什么；
- 函数是否产生输出或修改外部状态。

计算函数可以尽量保持无副作用：

```c
int add_three(int first, int second, int third)
{
    return first + second + third;
}
```

打印函数则明确承担 I/O：

```c
void print_total(int total)
{
    printf("总分：%d\n", total);
}
```

把计算和打印混在一个函数里并非永远错误，但会降低复用和单元测试的灵活性。

## 3. 拆分的边界

函数太大时可以按步骤拆分；函数太碎时，调用关系会变得难以追踪。优先寻找“有独立名字、独立输入输出、可以单独验证”的逻辑块。不要为了减少重复而传入一堆互相无关的参数。

## 填空任务

1. 修改脚本中的三个成绩；
2. 为总分、平均分和报告输出分别说明职责；
3. 给其中一个计算函数增加边界处理；
4. 暂时把一个函数的实现复制进 `main`，比较可读性后恢复；
5. 为每个函数写一句“输入 → 处理 → 输出”的说明。

## 自测题

1. 函数拆分的主要目的是什么？
2. 为什么函数名应该体现职责？
3. 计算函数和打印函数有什么不同？
4. 函数参数很多时，可能说明什么设计问题？
5. 一个函数太大或太碎各有什么影响？

## 验收标准

- [ ] 能按职责拆出至少两个函数；
- [ ] 能说明每个函数的输入和输出；
- [ ] 计算函数可以独立调用和验证；
- [ ] 能指出一个不必要的副作用。
