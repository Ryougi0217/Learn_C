# 第 13 课：项目目录设计

## 学习目标

为一个小型 C 项目划分 `include`、`src`、`tests` 和构建产物目录，形成清晰的文件拓扑。

## 核心概念

- `include/` 放对外头文件，`src/` 放实现。
- 测试代码与生产代码分开，避免测试入口混入正式程序。
- 构建产物可以集中到 `build/`，减少源目录噪声。
- 目录设计应服务于依赖边界，而不是为了层级多而多。

## 完整示例

```text
project/
├── include/
│   └── stats.h
├── src/
│   ├── main.c
│   └── stats.c
├── tests/
│   └── test_stats.c
├── build/
├── Makefile
└── README.md
```

## 练习任务

1. 为“文件初检工具”画出目录树。
2. 标出哪些头文件属于公共接口，哪些函数只能在源文件内部使用。
3. 设计 `build/debug` 和 `build/release` 的产物位置。
4. 解释为什么不应把生成的可执行文件和临时目标文件随意放在 `src` 中。

## 本课检查点

- [ ] 我能为小型 C 项目画出清晰目录树。
- [ ] 我能区分公共文件、实现文件、测试文件和构建产物。
- [ ] 我能说明目录设计如何帮助依赖管理。
