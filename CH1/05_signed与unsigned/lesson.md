# 第 5 课：`signed` 与 `unsigned`

## 本课目标

完成本课后，你应该能够：

- 说明有符号整数和无符号整数能表示的数值范围差异；
- 理解无符号运算的模运算特征；
- 识别有符号/无符号混合比较的风险；
- 对来自 `sizeof` 的 `size_t` 保持类型意识。

## 1. 有符号和无符号

默认的 `int` 是有符号整数，可以表示负数、零和正数。`unsigned int` 只表示非负数，因此在相同位数下能覆盖更大的非负范围。

`signed` 和 `unsigned` 不只是“正负号开关”，它们还会影响表达式中的类型转换。特别是有符号整数与无符号整数混合运算或比较时，较小类型可能被转换成无符号类型。

## 2. 无符号回绕

无符号整数的运算按模 `2^N` 进行，具体 `N` 取决于该类型的位数。例如：

```c
unsigned int value = 0U;
value = value - 1U;
```

结果会变成该类型能表示的最大值，而不是负数。这是语言规则允许的行为；但它仍可能造成业务逻辑错误。

有符号整数溢出则不能用同样方式理解，不能依赖它“回绕”。

## 3. 混合比较

在常见实现中：

```c
int signed_value = -1;
unsigned int unsigned_value = 1U;

if (signed_value < unsigned_value) {
    /* 结果可能与直觉不同 */
}
```

由于类型转换，`-1` 可能先转换成很大的无符号值，比较结果就不是“负数小于正数”的直觉。编译时可增加 `-Wsign-conversion` 帮助发现这类代码。

`size_t` 通常是无符号类型。循环下标、长度和 `sizeof` 结果混用时，要特别注意比较双方的类型和空值边界。
