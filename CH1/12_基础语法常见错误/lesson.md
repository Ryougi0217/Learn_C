# 第 12 课：基础语法常见错误

## 本课目标

完成本课后，你应该能够：

- 识别缺少分号、标识符拼写错误和括号不匹配；
- 根据编译器报告的上下文定位根因；
- 区分语法错误、类型/格式警告和运行逻辑错误；
- 用最小改动修复问题，并重新构建验证。

## 1. 常见错误类型

| 错误 | 典型表现 | 排查方向 |
| --- | --- | --- |
| 缺少分号 | `expected ';'`、`expected ','` | 查看当前行和上一条声明/表达式 |
| 括号不匹配 | `expected ')'` 或错误位置连锁偏移 | 从最近的 `(`、`{` 开始配对 |
| 字符串引号不匹配 | `missing terminating " character` | 检查字符串两侧的 `"` |
| 标识符拼写错误 | `undeclared identifier` | 对照声明处逐字符检查 |
| 格式说明符错误 | warning 或错误输出 | 对照表达式真实类型 |
| 逻辑写错 | 能编译但结果不对 | 增加输入和输出实验 |

编译器的箭头位置是重要线索，但不一定就是最早的错误位置。一个漏掉的分号可能让后面多行都无法正确解析。

## 2. 用宏控制错误实验

`practice.c` 的普通主干可以直接编译；三个错误分支则各自包含一个故意的错误。先一次只打开一个错误宏：

```
gcc -std=c17 -Wall -Wextra -pedantic -DBROKEN_SEMICOLON practice.c -o practice
gcc -std=c17 -Wall -Wextra -pedantic -DBROKEN_NAME practice.c -o practice
gcc -std=c17 -Wall -Wextra -pedantic -DBROKEN_PAREN practice.c -o practice
```

每次只打开一个宏，记录错误等级、文件名、行号和关键描述。不要把所有错误一次性打开，否则诊断会互相干扰。

## 3. 修复闭环

面对错误时使用固定闭环：

1. 复制或保存完整诊断；
2. 找到诊断指向的源代码上下文；
3. 只做一个最小修复；
4. 重新编译；
5. 再运行并确认行为没有被意外改变。

## 填空/修改任务

1. 先编译并运行普通主干；
2. 分别使用三个宏触发错误；
3. 每次只修复一个错误；
4. 用警告选项重新构建；
5. 为每类错误写一句“我如何确认它已修复”。

## 自测题

1. 为什么漏掉一个分号会导致后面多行报错？
2. 编译器的错误箭头一定指向根因吗？
3. 未声明标识符和格式说明符错误有什么不同？
4. 为什么建议每次只打开一个错误分支？
5. 程序能够编译但输出错误，是否一定是语法错误？
