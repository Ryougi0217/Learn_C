# 第 6 课：字符串结尾的 `\0`

## 本课目标

完成本课后，你应该能够：

- 说明 `\0` 在 C 字符串中的作用；
- 区分字符数量、数组容量和包含结尾标记的存储空间；
- 手动构造一个合法 C 字符串；
- 识别没有 `\0` 时使用 `%s` 的风险。

## 1. `\0` 是什么

`\0` 是数值为 0 的字符，也叫 NUL 字符。在 C 中，字符串函数和 `%s` 通常通过它判断字符串在哪里结束。

例如：

```c
char word[6] = {'h', 'e', 'l', 'l', 'o', '\0'};
```

可见字符有 5 个，但数组需要 6 个位置：前 5 个保存 `hello`，最后 1 个保存 `\0`。

## 2. 容量不等于字符串长度

对于上面的数组：

- 字符串内容长度是 5；
- 数组容量是 6 个 `char`；
- 最后一个元素是结尾标记，不属于可见文本。

如果把容量只分配成 5，却要保存 `hello` 和 `\0`，空间就不够。

## 3. 完整示例

```c
#include <stdio.h>

int main(void)
{
    char word[6] = {'h', 'e', 'l', 'l', 'o', '\0'};
    char prefix[4] = {'C', 'H', '3', '\0'};

    printf("word = %s\n", word);
    printf("prefix = %s\n", prefix);

    for (size_t i = 0; i < sizeof word; i++) {
        printf("word[%zu] numeric value = %u\n",
               i,
               (unsigned int) (unsigned char) word[i]);
    }

    return 0;
}
```

最后一个元素的数值会显示为 0。循环仍然访问它，但 `%s` 输出会在这里停止。

## 4. 不完整字符串的风险

下面这种数组没有足够空间保存结尾标记：

```c
char bad[5] = {'h', 'e', 'l', 'l', 'o'};
/* 不要对 bad 使用 printf("%s", bad); */
```

如果把 `bad` 当作字符串传给 `%s`，程序可能继续读取数组外的数据。未必每次都立刻崩溃，但行为不可靠。
