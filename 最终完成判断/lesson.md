# 最终完成判断

这不是“看完目录”就能勾选的清单。每一项都要有自己敲过、编译过、运行过或调试过的证据。

## 1. 独立项目

- [ ] 我能独立完成一个多文件项目。
- [ ] 我能写出头文件、实现文件、主程序和构建命令。
- [ ] 我能为项目写 README，说明功能、运行、测试和限制。

## 2. 内存和指针

- [ ] 我能画出一级指针和二级指针关系图。
- [ ] 我能解释栈、堆、数组、字符串和生命周期。
- [ ] 我能完成动态数组扩容和销毁。
- [ ] 我能指出越界、空指针、悬空指针、重复释放和释放后使用。

## 3. 数据建模和算法

- [ ] 我能使用结构体、枚举、typedef 和带标签联合体。
- [ ] 我能手写线性查找、二分查找和至少两种排序。
- [ ] 我能完成链表插入、查找、删除和销毁。
- [ ] 我能解释栈、队列、递归、DFS 和 BFS。

## 4. 调试和测试

- [ ] 我能使用严格编译器警告。
- [ ] 我能使用调试器断点、单步和调用栈。
- [ ] 我实际看过一次 ASan 报告。
- [ ] 我实际看过一次 UBSan 报告。
- [ ] 我为正常、边界和错误输入写过测试。
- [ ] 我能把失败缩小成最小复现。

## 5. 最终实操

任选一个综合项目，删除构建产物后重新开始：

```sh
gcc -std=c17 -Wall -Wextra -Wconversion -pedantic -g -O0 \
    ...所有需要的 .c 文件... -o app
./app
```

然后完成：

- [ ] 修改一个功能并补充测试。
- [ ] 故意制造一个可控错误，用 Sanitizer 定位。
- [ ] 修复错误并重新运行全部测试。
- [ ] 一周后不看答案重写核心数据结构或统计函数。
- [ ] 阅读一个 300～500 行的基础 C 项目，并画出模块关系。

## 通过标准

只有当你能在没有复制答案的情况下重新写出核心函数，并能解释每个资源的生命周期和每个边界条件，才算真正完成这套 C 学习路径。
