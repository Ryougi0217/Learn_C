# 第 17 课：文件与二进制数据验收

本课不额外提供脚本。请使用前面课程的脚本和你自己的测试文件完成验收。

## 概念验收

1. `FILE *` 保存的是什么？为什么不能把它当成文件内容缓冲区？
2. `"r"`、`"w"`、`"a"` 和二进制模式分别有什么含义？
3. `fread` 和 `fwrite` 的返回值表示什么？
4. 为什么循环结束后还要检查 `ferror`？
5. `fseek`、`ftell` 和 `SEEK_END` 如何配合得到文件大小？
6. 为什么二进制文件需要明确固定宽度类型和字节序？
7. 文件扩展名和文件签名有什么区别？
8. 为什么文件初检应该限制读取缓冲区大小？

## 操作验收

准备以下文件：

- 空文件；
- 一行文本文件；
- 含有不可打印字节的二进制文件；
- 一个超过 16 字节的文件；
- 不存在的路径。

至少完成：

```sh
gcc -std=c17 -Wall -Wextra -Wconversion -pedantic practice.c -o practice
./practice
```

并记录：

- 打开失败时的返回值和错误输出；
- 短文件时实际读取的字节数；
- 文件头十六进制输出；
- 签名识别结果；
- 分块哈希结果；
- 文件尾部附加数据判断。

## 代码验收

- [ ] 所有成功的 `fopen` 都能找到对应的 `fclose`。
- [ ] 所有 `fread`、`fwrite`、`fseek`、`ftell` 都检查了结果。
- [ ] 不把二进制缓冲区交给字符串函数。
- [ ] 不把文件大小直接转换成不安全的小整数类型。
- [ ] 初检工具不会修改输入文件。
- [ ] 我能解释一个真实测试文件的前 16 个字节。
