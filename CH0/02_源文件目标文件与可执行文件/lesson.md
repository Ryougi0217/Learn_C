# 第 2 课：源文件、目标文件与可执行文件

## 本课目标

完成本课后，你应该能够区分：

- 人直接编写的源文件；
- 编译但尚未完成链接的目标文件；
- 可以被操作系统加载运行的可执行文件；
- “生成了文件”和“程序能正常运行”这两个不同的验收点。

## 1. 三种文件分别是什么

### 源文件

`.c` 文件是 C 源文件，内容是供人阅读和编译器处理的文本。它描述数据、函数和程序逻辑。`practice.c` 就是本课的源文件。

### 目标文件

目标文件通常以 `.o`（GCC/Clang）或 `.obj`（MSVC）结尾。它已经经过了编译/汇编，包含机器代码片段和符号信息，但通常还没有完成最终的库函数绑定，因此不一定能直接运行。

### 可执行文件

可执行文件是链接器整理出的最终程序。在 Linux/WSL 中常见的是没有扩展名的文件；Windows 中常见的是 `.exe`。它通常可以直接由操作系统加载运行。

可以把关系记成：

```text
practice.c  --编译/汇编-->  practice.o  --链接-->  practice
```

目标文件不是“半个可执行文件”这么简单：它还可能保留对其他目标文件或库的未解析引用。它的核心特点是“可重定位的程序片段”。

## 2. 分两步构建

GCC/Clang 风格命令：

```text
gcc -std=c17 -Wall -Wextra -pedantic -c practice.c -o practice.o
gcc practice.o -o practice
./practice
```

其中：

- `-c` 表示只生成目标文件，不进行最终链接；
- 第一个命令的输入是 `.c`，输出是 `.o`；
- 第二个命令的输入是 `.o`，输出是可执行文件；
- 如果目标文件不存在、名称写错，第二步就无法完成。

如果使用 MSVC，可以在 Visual Studio Developer Command Prompt 中尝试：

```text
cl /std:c17 /W4 /c practice.c
link practice.obj /out:practice.exe
practice.exe
```

具体生成的辅助文件可能因编译器版本而不同。本课只验收 `.c`、目标文件和可执行文件三者的关系。

## 3. 观察文件产物

编译前后分别列出当前目录内容，观察哪些文件新增了。不要只看 IDE 的“解决方案资源管理器”，因为本课的重点是理解构建命令实际产生的文件。

可以记录：

| 阶段 | 输入 | 输出 | 是否能直接运行 |
| --- | --- | --- | --- |
| 源代码 | 无 | `practice.c` | 否 |
| 生成目标文件 | `practice.c` | `practice.o`/`practice.obj` | 通常否 |
| 生成可执行文件 | `practice.o`/`practice.obj` | `practice`/`practice.exe` | 是 |

## 自测题

1. `-c` 参数改变了构建过程的哪一部分？
2. 为什么目标文件通常不能像可执行文件一样直接运行？
3. `.o` 和 `.obj` 的差别主要来自什么？
4. 如果链接阶段提示找不到符号，问题更可能发生在源代码、编译阶段还是链接阶段？说明理由。
5. 可执行文件没有扩展名时，为什么仍可能是一个可运行程序？
