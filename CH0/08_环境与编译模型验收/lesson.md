# 第 8 课：环境与编译模型验收

本课不新增脚本。请使用 CH0 前 7 课的练习文件，独立完成下面的验收任务，并把命令、输出、错误信息和解释整理成一份记录。

## 验收目标

你需要证明自己不只是“会在 IDE 中点击运行”，而是能够解释一次 C 程序从源代码到运行结果的完整过程。

## 任务 A：环境确认

1. 选择一个可用的 C 编译器。
2. 在终端输出版本信息。
3. 记录终端类型、操作系统/环境（例如 PowerShell 或 WSL）和编译器版本。
4. 说明你运行可执行文件时使用的命令。

## 任务 B：一次完整构建

选择 `01_开发环境与编译器/practice.c` 或 `02_源文件目标文件与可执行文件/practice.c`：

1. 用警告选项编译；
2. 运行可执行文件；
3. 说明源文件、目标文件和可执行文件分别在哪里；
4. 如果使用分步构建，分别记录编译和链接命令。

## 任务 C：观察构建流水线

使用 `03_预处理编译汇编与链接/practice.c`：

1. 生成预处理文件；
2. 生成汇编文件；
3. 生成目标文件；
4. 生成并运行最终可执行文件；
5. 对 `.i`、`.s`、`.o` 和可执行文件各写一句用途说明。

## 任务 D：终端独立操作

使用 `04_终端编译和运行/practice.c`：

1. 在终端确认当前目录；
2. 编译并运行一次不带参数的程序；
3. 再运行一次带参数的程序；
4. 故意使用错误的源文件名，记录编译器信息；
5. 恢复正确命令并再次运行。

## 任务 E：错误和警告诊断

使用 `05_编译错误与编译警告/practice.c`：

1. 先记录默认构建出现的警告；
2. 修复所有警告；
3. 使用 `-DTRY_BROKEN` 观察并修复语法错误；
4. 使用 `-Werror` 完成一次零警告构建；
5. 用自己的话解释 error、warning 和运行时错误的区别。

## 任务 F：多文件构建

使用 `06_c文件与h文件` 中的三个文件：

1. 分别编译两个 `.c` 文件；
2. 把两个目标文件链接起来；
3. 运行程序；
4. 从链接命令中去掉实现文件的目标文件，记录错误；
5. 解释 `.h` 文件、实现 `.c` 文件和调用方 `.c` 文件的职责。

## 任务 G：Sanitizer 验收

使用 `07_调试构建与Sanitizer入门/practice.c`：

1. 保留越界条件，使用 AddressSanitizer 构建并运行；
2. 记录错误类别、源码行号和越界原因；
3. 修复边界后重新构建并运行；
4. 生成一个普通 debug 版本和一个 release 版本；
5. 说明 Sanitizer 能检查什么、不能证明什么。

## 最终问答

请脱离目录文件，用自己的话回答：

1. `.c`、`.h`、`.o/.obj` 和可执行文件的关系是什么？
2. 预处理、编译、汇编、链接分别解决什么问题？
3. 终端编译失败时，你如何判断问题来自目录、命令还是源代码？
4. 为什么“编译成功”不等于“程序正确”？
5. 为什么应当保留警告并使用 Sanitizer，而不是只看程序有没有输出？

## 通过标准

- [ ] A～G 七项任务都有命令和结果记录；
- [ ] 能独立完成一次多文件构建；
- [ ] 能解释至少一个编译错误、一个编译警告和一个 Sanitizer 报告；
- [ ] 能在修复后重新构建并验证；
- [ ] 能用一张流程图或一段文字说明“源代码 → 可执行文件 → 运行结果”。

如果某项因为本机工具不可用而无法完成，请记录“工具名称、完整报错、尝试过的命令和当前结论”，不要把未完成写成已通过。
