# 第 1 课：开发环境与编译器

## 本课目标

完成本课后，你应该能够：

- 说出编辑器、编译器、终端和调试器分别负责什么；
- 查看当前机器上是否存在 C 编译器；
- 编译并运行一个最小的 C 程序；
- 记录“我使用的命令”和“命令产生的结果”，而不是只依赖 IDE 的运行按钮。

## 1. 先建立角色分工

写 C 程序时，常见工具不是同一个东西：

| 工具 | 主要职责 | 例子 |
| --- | --- | --- |
| 编辑器或 IDE | 编写、保存、搜索代码 | VS Code、Visual Studio |
| 编译器 | 把 C 源代码转换为更低层的程序产物，并报告错误/警告 | GCC、Clang、MSVC |
| 终端 | 输入命令、查看输出、切换目录 | PowerShell、Windows Terminal、Bash |
| 调试器 | 在程序运行过程中暂停并观察状态 | GDB、LLDB、Visual Studio Debugger |

Visual Studio 可以替你调用编译器和调试器，所以“点击运行”很方便；但为了真正理解编译模型，本章会逐步把这些动作拆成命令。

## 2. 编译器探测

在终端中分别尝试自己环境里可用的命令：

```text
gcc --version
clang --version
cc --version
```

Windows 的 Visual Studio 开发者命令提示符中还可以尝试：

```text
cl
```

不要求所有命令都存在。你只需要找到至少一个可用的编译器，并把完整版本信息记下来。`cl` 通常只能在配置过 MSVC 环境变量的开发者命令提示符中直接使用。

## 3. C 程序最小结构

打开同目录下的 `practice.c`，观察它包含的四个关键部分：

1. `#include <stdio.h>`：请求使用标准输入输出声明；
2. `main` 函数：程序通常从这里开始执行；
3. `printf`：向终端输出文字；
4. `return 0`：向操作系统报告正常结束。

使用 GCC/Clang 风格编译器时，可以运行：

```text
gcc -std=c17 -Wall -Wextra -pedantic practice.c -o practice
```

然后运行：

```text
./practice
```

Windows PowerShell 中，如果生成的是 `practice.exe`，运行形式通常是：

```text
.\practice.exe
```

MSVC 的基础命令可以写成：

```text
cl /std:c17 /W4 practice.c
practice.exe
```

`-Wall`、`-Wextra`、`-pedantic` 和 `/W4` 都是在请求编译器多报告一些可疑之处；它们不是“把所有错误变成警告”的开关。

## 4. 填空任务

在 `practice.c` 中完成这些任务：

- 把姓名字符串改成你希望看到的称呼；
- 把问候语改成自己的句子，但保留 `%s` 与变量之间的对应关系；
- 编译时打开警告选项；
- 分别记录“编译成功时终端显示了什么”和“程序运行时显示了什么”。

先不要用 IDE 的运行按钮代替命令。若命令失败，保留完整错误信息，先判断它是“命令不存在”“当前目录不对”，还是“源代码/参数有问题”。

## 自测题

1. 编译器和编辑器的职责有什么不同？
2. `main` 函数返回 `0` 通常表达什么？
3. `./practice` 与 `gcc practice.c -o practice` 分别做什么？
4. 为什么建议在学习阶段打开编译器警告？
5. 如果终端提示找不到 `practice.c`，你首先检查什么，而不是立刻改代码？
