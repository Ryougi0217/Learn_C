# 第 3 课：预处理、编译、汇编与链接

## 本课目标

完成本课后，你应该能够：

- 按顺序说出 C 构建的四个主要阶段；
- 用命令分别请求预处理文件、汇编文件、目标文件和可执行文件；
- 认识到不同阶段的产物用途不同；
- 不把“编译器”只理解成一个瞬间完成的黑盒动作。

## 1. 四个阶段

### 预处理（preprocess）

预处理器处理以 `#` 开头的指令，例如 `#include` 和 `#define`。它会展开头文件、替换宏，并处理条件编译。结果通常仍然是接近 C 语言的文本。

### 编译（compile）

编译器把预处理后的 C 代码分析、优化，并转换成汇编语言。这个阶段会检查语法、类型和很多语义问题。

### 汇编（assemble）

汇编器把汇编文本转换成目标文件中的机器指令和符号信息。目标文件通常还需要重定位。

### 链接（link）

链接器把一个或多个目标文件，以及需要的运行库/系统库组合起来，解析跨文件或库函数引用，生成最终可执行文件。

流程可以写成：

```text
practice.c
   ↓ -E
practice.i       预处理结果
   ↓ -S
practice.s       汇编文本
   ↓ -c
practice.o       目标文件
   ↓ 链接
practice         可执行文件
```

不同平台可能使用不同扩展名或添加额外中间产物，但阶段关系不变。

## 2. 用命令显式观察阶段

以下是 GCC/Clang 风格命令：

```text
gcc -std=c17 -Wall -Wextra -pedantic -E practice.c -o practice.i
gcc -std=c17 -Wall -Wextra -pedantic -S practice.c -o practice.s
gcc -std=c17 -Wall -Wextra -pedantic -c practice.c -o practice.o
gcc practice.o -o practice
```

说明：

- `-E` 通常停在预处理结束处；
- `-S` 通常生成汇编文本；
- `-c` 通常生成目标文件；
- 不加这些“停下来的”选项时，编译器驱动程序会继续完成链接。

打开 `practice.i`，搜索自己定义的宏名称；打开 `practice.s`，观察它已经不是普通 C 语法。汇编内容会因操作系统、CPU、编译器版本和优化选项不同而变化，不要求逐行背诵。

## 3. 为什么需要链接

`printf` 的实现不在你的 `practice.c` 文本中。头文件主要提供声明，让编译器知道如何检查调用；真正的实现通常来自标准库，链接阶段负责把需要的库代码和符号关系接起来。

这也是“头文件里有声明，不等于已经有实现”的一个例子。后续学习多文件项目时，你会看到自己的 `.c` 文件也可以通过链接互相协作。

## 自测题

1. `#include` 主要在哪个阶段处理？
2. 汇编文件与目标文件有什么区别？
3. 为什么只生成目标文件时通常还不能得到最终可执行文件？
4. `printf` 的声明和实现分别可能来自哪里？
5. 如果 `-E` 已经失败，后面的汇编和链接阶段是否有意义？为什么？
